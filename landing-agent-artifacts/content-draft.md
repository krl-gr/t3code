## Pain Blocks

- Your agents live in different terminals, but your work needs one place to land.
- You need to see what changed before you commit it.
- Parallel agent work needs branches, status, and recovery, not a pile of shells.
- Switching CLIs should not mean switching workflows.

## Product Explanation

1. Pick a project and start a thread.
2. Choose the CLI/provider/model you want for that task.
3. Watch the agent run with approvals, terminal output, and structured progress in the same workspace.
4. Review changed files and diffs without leaving the app.
5. Commit, push, or open a PR from the same surface.
6. Connect local, network, or SSH environments when work lives on another machine.
